# Claude Code の設定

Windows と WSL で同じ設定を使うため、共通部分を chezmoi で管理する。

| ファイル | 内容 |
|---|---|
| `home/.claude-settings.json` | 共通の設定(プラグイン、マーケットプレイス、フックなど)。プラグインの書き方は｢プラグイン｣ |
| `home/dot_claude/modify_settings.json` | 共通の設定を `settings.json` へマージする (chezmoi のテンプレートなので両 OS で動く)。review-loopが台帳を置くディレクトリへの許可も足す(「review-loopの台帳の置き場」) |
| `home/dot_claude/CLAUDE.md` | ユーザー全体の指示。dotfilesで設定を管理していることのほか、日本語の表記、タスクの進め方、コードコメント、コミットとレビューの決まり、技術的な知見の記録を提案する決まりを書く。日本語の表記の一部は、フックが検査してClaudeに報告する(｢日本語の表記を検査するフック｣)。それ以外は指示として読まれるだけで、強制はしない。`agent`には置かない |

| `home/dot_claude/pstack-models.md` | pstack のロールごとのモデル。`/setup-pstack` が書き、`CLAUDE.md` の `@` 行で読み込む |

| `home/.hooks-src/ja-style/` | 足した行の日本語の表記を検査するフック(Go) |

## 反映

```bash
chezmoi diff    # 差分を見るだけ
chezmoi apply   # 反映する
```

- `settings.json` は Claude Code 自身も書き換えるので、丸ごと置き換えずにマージする。
- Claude Code が書き換えると並び順が変わるので、`chezmoi status` には差分が出続ける。`doctor` はこのファイルを比べず、フックの登録だけを確かめる。
- モデルと effort は画面から変える個人の選択なので、共通の設定に入れない。
- 環境固有のキーは残り、同じキーは共通の設定が優先される。配列は丸ごと置き換わるので、共通の設定にある `hooks.PreToolUse` に環境固有のフックを足しても次の反映で消える。
- フックはソースが変わると自動でテストとビルドが走る。テストが落ちたら置き換えない。

どちらかの環境で `/config` などから変えた設定を共通にしたいときは、`home/.claude-settings.json` に書き写して反映し直す。

## プラグイン

プラグインは`home/.claude-settings.json`の`enabledPlugins`に`<プラグイン>@<マーケットプレイス>`で書き、`true`で有効、`false`で無効にする。公式の`claude-plugins-official`のほかのマーケットプレイスは、`extraKnownMarketplaces`に出どころ(`source`)を書く。

第三者のマーケットプレイスは、`source`を`github`にし、`ref`にコミットのハッシュ(40桁の小文字)を書いて固定する。プラグインはスキルと同じくエージェントへの指示なので、知らないうちに中身が変わらないようにする(`docs/skills.md`の｢方針｣)。

```json
"pstack-claude": {
  "source": {
    "source": "github",
    "repo": "michael-denyer/pstack-claude",
    "ref": "<40桁のハッシュ>"
  },
  "autoUpdate": true
}
```

- `ref`にコミットのハッシュを書けるのは、Claude Code 2.1.324から。
- `autoUpdate`は`source`と並べて書く。第三者のマーケットプレイスは既定では自動で更新されない。`ref`がコミットのハッシュなら、更新しても固定したコミットより先には進まない。
- `ref`を書き換えて反映すると、次に対話のセッションを始めたときに、Claude Codeが固定したコミットでマーケットプレイスを取り直す。それまでは`claude plugin`のコマンドから、そのマーケットプレイスが見えない。`claude -p`の実行では取り直さない。
- 入れたプラグインは、取り直した後も前の版のまま。`claude plugin update <プラグイン>@<マーケットプレイス>`で、固定したコミットの版に入れ替え、セッションを始め直す。`autoUpdate`が`true`でも、起動しただけでは入れ替わらなかった(2026-11-18にClaude Code 2.1.325で確かめた)。
- マーケットプレイスの固定で止まるのは、`marketplace.json`がマーケットプレイスの中の相対パス(pstackの`./plugins/pstack`など)で指すプラグインだけ。別のリポジトリを指すプラグインは、マーケットプレイスを固定しても止まらない。
- `ref`の無いマーケットプレイスは、自動では更新されず、最初に入れた版のままになる。

固定は`provision/update-skills.sh`が、スキルと同じく上流の既定のブランチの最新に上げる。対象は、`source`が`github`で`ref`がコミットのハッシュのものだけ。週1回のPRにも、スキルと並んで出る(`docs/skills.md`の｢更新する｣)。

```bash
bash ~/dotfiles/provision/update-skills.sh --dry-run
bash ~/dotfiles/provision/update-skills.sh pstack-claude
```

固定を上げて`chezmoi apply`で反映したら、端末ごとに対話のセッションを1回始めてマーケットプレイスを取り直させ、プラグインを入れ替える。

```bash
claude plugin update pstack@pstack-claude
```

共通の設定からプラグインやマーケットプレイスを消しても、今ある端末からは消えない。マージは`settings.json`にあるキーを消さないため。端末ごとに、次を実行して消す。

```bash
claude plugin uninstall <プラグイン>@<マーケットプレイス>
claude plugin marketplace remove <マーケットプレイス>
```

## 環境で変わる指示

`CLAUDE.md`はどの環境でも同じ中身にし、環境で変わる指示は話題ごとのファイルにして`home/dot_claude/rules/`に置く。Claude Codeは`~/.claude/rules/`の`.md`も、`CLAUDE.md`と同じくユーザー全体の指示として読む。どのファイルをどの環境に置くかは`home/.chezmoiignore`で決める。

| ファイル | 内容 | 置く環境 |
|---|---|---|
| `plamo.md` | PLaMo 3 Translateの使い方(`docs/tools.md`) | Windowsだけ。WSLのLinuxのプロセスはNATのネットワークで動くので、Windowsの`127.0.0.1`で待ち受けるサーバーに届かない |
| `secrets.md` | APIキーを`op-run`で渡す決まり(`docs/secrets.md`) | mac以外 |
| `pr.md` | PRの作り方と、レビューコメントへの返信の決まり | chezmoiのデータで`work`が`true`の機械(`docs/mac.md`) |

- `work`が無い設定(`work`ができる前に`chezmoi init`した機械の設定)では、`false`として扱う。
- `work`を`false`に戻しても、すでに置いた`pr.md`は消えない。chezmoiは無視するようになったファイルを消さないため。
- `tests/ci/render.sh`は、指示(`CLAUDE.md`と`rules/`)にPLaMo、`op-run`、PR運用が出るかを環境ごとに確かめる。`CLAUDE.md`がどの環境でも同じことと、`work`が無い設定で適用できることも確かめる。

## compact

会話をcompactする時期を、既定より早める。main会話は毎回、文脈全体をキャッシュから読み直すので、文脈が小さいほど1回に送るトークンが減る。

- `autoCompactWindow: 500000`: 50万トークンでcompactする。既定では、1Mのモデルで約97万トークンまで待つ。値はモデルのコンテキストウィンドウで頭打ちになる。`/autocompact`で決めた値はモデルごとに`modelSettings`へ保存され、こちらより優先される。
- `idleCompaction: true`: 20万トークン以上の会話から離れると、1時間のキャッシュが切れる前にcompactする。戻ったときに、会話全体をキャッシュへ書き直さずに済む。1時間のキャッシュが使われるのは定額プランのmain会話だけなので、キャッシュが5分で切れるサブエージェントでは動かない。

compactが増えると、序盤の細かい指示が要約で落ちやすくなる。決めたことは会話の外(issue、PR、コミット)に残す。

## review-loopの台帳の置き場

`modify_settings.json`が`permissions.additionalDirectories`に`<ホーム>/.local/state/review-loop`を足す。review-loopは台帳をここに置く(`home/dot_claude/skills/review-loop/SKILL.md`の0)。このディレクトリは作業ディレクトリと同じ扱いになり、読むときに確認が出ない。書き込みの確認は今の権限モードに従い、`acceptEdits`では出ない。

- ほかの置き場は向かない。セッションのscratchpadは、セッションが終わると消えることがあり、別のセッションからは見つからない。リポジトリの`.git`と`.claude`はClaude Codeの保護パスで、書き込みのたびに確認が出る。作業ツリーに置くと、リポジトリごとに無視の規則を足さない限り、台帳が`evidence.sh`の指紋に入る。
- 足すパスはchezmoiの`.chezmoi.homeDir`から作った絶対パスにする。`~`で書いたパスをClaude Codeが展開するかは、公式の文書に書かれていない。
- `additionalDirectories`はファイルを読み書きできるようにするだけで、そこからCLAUDE.md、スキル、設定を読み込まない(公式の文書の「Additional directories grant file access, not configuration」)。
- Claude Codeは、セッションの開始時に無い追加のディレクトリを、警告を出さずに外す(本体のコードで確かめた)。そこで、chezmoiが`home/dot_local/state/review-loop/.keep`から、このディレクトリを反映のときに作る。
- 配列は丸ごと置き換わるので、環境ごとに`permissions.additionalDirectories`へ足したディレクトリは、反映のたびに消える。
- `agent`と`research`には`~/.claude`を置かないので、この許可も入らない。台帳の置き場も作らない(`home/.chezmoiignore`)。
- `tests/ci/render.sh`は、反映で`permissions`に足されるのが台帳の置き場だけであることと、既存の`permissions.allow`が残ることを確かめる。

## 使用量の記録

新しいセッションを始めるたびに、`home/.claude-settings.json`のSessionStartのフックが、`usage-log collect`をバックグラウンド(`async`)で動かす。Claude Codeがセッションのログを30日で消すので、このコマンドはログが消える前に、API呼び出しごとのトークン数と、その時刻やスキルなどの属性を`~/.local/state/usage/usage.sqlite3`に写す。会話の中身は写さない。Codexの記録(`~/.codex/sessions`と`archived_sessions`)も同じように写す。集計には`usage-log report`を使う(`docs/tools.md`)。

- 初回は残っているログを全部読むので、数分かかる(2026-11-14に約1,900ファイルで約2分)。2回目からは、新しいログと、大きさか更新時刻が変わったログだけを読む。
- 非同期のフックの失敗は画面に出ない。uvが見つからないときも、記録が増えないだけになる。記録が増えているかは、`usage-log report --by day`で確かめる。
- ログの形式はClaude Codeの内部のもので、公式には版で変わりうるとされている。`usage-log`は、JSONとして読めない行と、読めても形の違う行(トークン数を数として読めない、スキルやモデルが文字列でないなど)を、その行だけ飛ばして数える。飛ばした行の数は、`collect`の出力と、`report`の表の最後に出る。フックの`collect`は何も出さないので、形式が変わって記録される呼び出しが減っていないかは、`report`で確かめる。数はログごとに最後に読んだときのもので、伸びたログを読み直すと数え直す。
- サブエージェントの呼び出しは、自分にスキルが無く、それを起こした親の呼び出しにもスキルが無いと、「(なし)」に入る(2026-11-14に、サブエージェントの呼び出しの76%)。workflowで動いたサブエージェントは、`.meta.json`に親の呼び出しが無いので、自分にスキルが無ければ「(なし)」に入る。
- 呼び出しのスキルは、ログの`attributionSkill`による。スキルを呼ぶと、そのターンの残りの呼び出しは、そのスキルに付く。次のターンで外れる。ターンは、利用者の発言のほか、バックグラウンドで動いたサブエージェントの報告や、バックグラウンドの完了通知でも始まる(前景のサブエージェントの報告は、同じターンの中に返る)。ターンの途中の自動compactでは外れない(2026-11-14に手元のログで確かめた)。このため、バックグラウンドのサブエージェントを待つ仕事では、最初の通知より後の本体の呼び出しと、そこから起こしたサブエージェントが「(なし)」に入る。スラッシュコマンドで呼んだスキルは、そのターンの最初の応答から付く。
- SSHのリモートのセッションでは、サブエージェントのログが`subagents/`の外にあり、`.meta.json`に種類も説明も無い。こうしたサブエージェントの呼び出しは、`report --by agent`と`--by agent-type`で「(種類不明)」にまとまる。手元のサブエージェントでも、`.meta.json`が無いか、そこに種類が書かれていなければ、同じく「(種類不明)」に入る。
- セッションを再開すると、サブエージェントのログが`.meta.json`を持たずに新しいセッションへ写される。forkのログは、親の履歴を写して持つ。同じ応答は`message.id`で1回だけ数え、種類、説明、スキルは、元のログらしい方(種類が分かる、本体、fork、種類不明の順)のものを使う。トークン数は大きい方を使う。
- Claude Code 2.1.284〜2.1.304(2026-09-29〜10-21)が書いたサブエージェントのログでは、応答の最後の行も、出力トークン数が途中の値のことが多い(2026-11-14の手元のログで、この版のサブエージェントの応答の約4分の3)。ログに最後の値が無いので、この期間のサブエージェントの出力と費用は少なく出る。2.1.308からは、ほとんど起きていない。

### 大きい仕事の上限

多くの成果物を作る仕事や長いループが、週の枠を使い切ってほかの作業を止めないように、上限を決められる。`usage-log cap 70`で、週の枠(全モデル)の消費率が70%に達したら大きい仕事を止める、と決める。消費率は、ほかの作業で使った分も含む。モデルごとの週の枠(「Weekly · Fable」など)は見ないので、そちらが先に尽きることはある。上限は記録と同じディレクトリの`weekly-cap`に書かれる。WindowsとWSLではホームが違うので、上限は決めた側のセッションにだけ効く。`usage-log cap`は今の上限を出し、`usage-log cap off`は上限を外す。リセットの前日に枠を使い切りたいときは、上限を外すか上げる。

- 大きい仕事の指示に、`usage-cap`で週の枠の上限を確かめながら進めるよう書く。本体は、仕事を始める前、単位を終えるたび、サブエージェントをまとめて起こす前に、小さいサブエージェントを起こし、`usage-cap`スキルで確かめさせる。サブエージェントは、上限のファイルと、デスクトップアプリの`get_usage`ツールが返す週の消費率(「Weekly · all models」)を読み、`CONTINUE`か`STOP`と報告を返す。`STOP`なら、本体は新しい単位を始めずに止まって報告する。上限は確かめるたびに読み直すので、仕事の途中で変えてもよい。
- 確かめをサブエージェントに任せるのは、本体でスキルを呼ぶと、そのターンの残りの呼び出しがスキルに付き、`report --by skill`で仕事の費用が`usage-cap`に入るため。サブエージェントの中でスキルを呼んでも、帰属は変わらない(2026-11-14の手元のログで、スキルを呼んだサブエージェント304件のうち303件で、呼んだ後の行の`attributionSkill`が呼ぶ前と同じだった)。確かめの費用は、起こした本体の呼び出しのスキル(無ければ「(なし)」)に入り、`usage-cap`には付かない。スキルの許可(`allowed-tools`)は呼んだターンの間しか効かないが、サブエージェントは確かめのたびに新しく呼ぶので、毎回効く。本体はスキルを呼ばないので、委ねる手順はスキルの一覧の説明(description)に書いてある。
- ただし、このデスクトップアプリのAgentツールでは、サブエージェントはいつもバックグラウンドで動く(2026-11-14)。その報告で本体の新しいターンが始まり、帰属が外れるので、確かめの後の本体の呼び出しは、仕事のスキルではなく「(なし)」に入る。大きい仕事の費用は、`report --by session`か`--by project`で見る。
- 止まるのは指示に従うエージェントだけで、フックのように強制はしない。フックで強制するには、フックから`get_usage`の消費率を読んで上限と比べる必要があるが、その手段を確かめていないため(MCPのツールを呼ぶ`mcp_tool`のフックは、ツールの出力を返すだけで、比べる処理を持てない)。
- スキルは消費率を`get_usage`から読むので、デスクトップアプリの中でしか使えない。ターミナルの`claude`には`get_usage`が無いので、上限があれば、スキルは`STOP`を返す(ステータスラインは消費率を受け取るが、デスクトップアプリでは動かない)。
- スキルの`allowed-tools`で、確認なしに使えるようにするのは、上限のファイルを読むことと`get_usage`を呼ぶことだけ。

## 署名回避を止めるフック

Bash / Edit / Write の実行前に動き、コミット署名を回避する操作を拒否する。

| 種類 | 例 |
|---|---|
| 署名を外すフラグ | `--no-gpg-sign`, `git tag --no-sign` |
| 一時的な設定の上書き | `git -c commit.gpgsign=false`, `git -c gpg.program=...` |
| 署名設定の変更 | `git config commit.gpgsign false`, `--unset`, 別のファイルを読ませる `include.path` と `includeIf.*.path` |
| 環境変数での回避 | `GIT_CONFIG_GLOBAL=...`, `HOME=... git` |
| `git commit` を通らないコミット | `git commit-tree`, `git fast-import` |
| 設定ファイルの直接編集 | `.gitconfig`, `.gitconfig.local`, `.git/config` |

設定の読み取りと通常の `git commit` は通る。署名できないときは、Claude が失敗を報告して止まるので、自分のターミナルでコミットする。

発動の確認は、Claude に次の無害なコマンドを実行させる。拒否されれば動いている。

```bash
true # hook test: --no-gpg-sign
```

### 制限

- コマンド文字列の照合なので、スクリプトファイルに書いて実行するなどの方法はすり抜ける。
- 禁止フラグに言及しただけのコマンド (コミットメッセージや `grep`) も拒否される。
- フックの起動に失敗すると、エラーを報告してコマンドは実行される。
- Windows ではコマンドの書き方が Git Bash 前提で、PowerShell では動かない。Claude Code は Git Bash があればそれを使う。
- Claude がフック自体や `settings.json` を書き換えることは止めていない。

確実に止めるには、GitHub のブランチ保護で署名を必須にする。

### Go で書いている理由

- Bash / Edit / Write の実行ごとに動くので、起動が速いほうがよい。計測では WSL で 4 ms、Windows で約 29 ms (Git Bash の起動分を除く) で、Perl や node より速かった。
- ビルド済みのバイナリを置くので、実行する環境にランタイムが要らない。
- 同じソースを Windows 用にもビルドできる。

### テスト

```bash
cd home/.hooks-src/block-signing-bypass && go test ./...
```

止めるコマンドと通すコマンドの一覧は `main_test.go` にある。回避方法を見つけたら、ここにケースを足してからルールを直す。

## 日本語の表記を検査するフック

`home/.hooks-src/ja-style/`は、EditとWriteの後に動くPostToolUseフック。足した行のうち日本語を含む行を、`home/dot_claude/CLAUDE.md`の｢日本語の表記｣の規則で検査し、違反の`ファイル:行`と直し方をClaudeに返す(exit 2)。

| 検査すること | 例 |
|---|---|
| 全角の英数字、丸括弧、カギカッコ、中黒 | `ＡＩ`、`（分）`、`「保存」`、`設計・開発` |
