# ユーザーガイドと技術文書

ガイドの仕事は、製品を使う人が、やりたいことを終えられること、調べたいことを引けること、仕組みを理解できること。1つのページは、このうち1つを仕事にする。

## 既定の問い

文書群の全体には、次の問いを置く。Xには、製品の面(コマンド、機能、連携先)と、issueや質問から拾った上位の作業を入れる。

| 問い | 答えるページの種類 |
|---|---|
| 初めて使う。最初に何をすればよいか | チュートリアル、導入の手順 |
| Xをしたい。手順はどこか | ハウツー |
| この設定、コマンド、APIの正確な仕様は何か | リファレンス |
| うまくいかない。このエラーは何で、どう直すか | トラブルシューティング |
| なぜこう動くのか。どれを選べばよいか | 解説 |
| 前の版から何が変わり、どう移行するか | 移行の手順 |

1つのページには、そのページに来る人の問いを置く。要るものは何か、手順は何か、うまくいったとどう分かるか、次にどこへ行くか。

## ページの種類

| 種類 | 読者の状態 | 中身 | 見分ける問い |
|---|---|---|---|
| チュートリアル | 学んでいる | 1つの成果物を最後まで作る道筋。手順ごとに見える結果 | 終えたとき、読者は何を作り終えているか |
| ハウツー | 作業中で、目的がある | 目的までの手順。前提、手順、結果の確かめ方 | 題を「〜する」と書けるか |
| リファレンス | 作業中で、事実を引きたい | 仕様の一覧。コードの構造と同じ並び | 上から読まずに、1項目だけ引けるか |
| 解説 | 理解したい | 背景、理由、選び方、比較 | 「なぜ」「どちらを」に答えているか |

プロジェクトが別の分類を既に使っているなら、それに従う。分類が揃っていることのほうが、どの枠組みかより効く。

## 混ざったページ

| 症状 | 直し方 |
|---|---|
| 手順の途中に、オプションの全一覧がある | 一覧をリファレンスへ移し、手順には使うものだけを残してリンクする |
| リファレンスの項目の前に、長い背景がある | 解説へ移し、項目からリンクする |
| ハウツーが、概念の説明から始まる | 説明を1〜2文にして解説へリンクし、手順を上に置く |
| チュートリアルが、機能の紹介の列になっている | 作るものを1つ決め、そこへ進まない手順を外す |
| 解説の中に、実行する手順がある | 手順をハウツーへ移す |

混在として直すのは、2つ目の種類がページのかなりの部分を占めるか、読者の作業を止めているときだけ。1〜2文の補足は混在ではない。分けすぎると、1つの作業に要る情報が何ページにも散る。分けた先が数行にしかならないなら、分けない。

## 枠組みを目的にしない

- 最上位の区分を、製品の機能の一覧にしない。読者の作業で分ける。
- どのページも入口になる。検索やリンクで途中のページに着く読者のために、ページの冒頭で、何のページか、誰向けか、何が前提かを言う。

## ページの中

- **手順。** 前提(要るもの、バージョン、権限)を、手順の前に置く。読者が始める前に確かめられる形で書く。1つの手順に1つの動作。どこで、何をするか、の順に書く。期待する結果を書く。方法が複数あるなら、勧める1つを書き、ほかは読者が実際に選ぶときだけ書く。最後に、次に進む先を書く。
- **例。** 実行できる最小の例を、網羅的な説明より先に置く。実際に動かして確かめ、出力を載せる。
- **リファレンス。** 網羅をコードから確かめる。CLIの`--help`、設定のスキーマ、公開APIの一覧と突き合わせ、文書に無い項目と、コードに無い項目を挙げる。
- **トラブルシューティング。** 見出しを、読者が目にする症状(エラーメッセージそのまま)にする。原因、確かめ方、直し方の順に書く。よく起きる失敗は、それが起きる手順のそばにも1行書く。
- **用語。** 最初に出る場所で、その文の中で定義する。1つの概念に1つの名前を使う。

## 全体の進め方

- 台帳の節の表の代わりに、ページの棚卸しを作る。ページ、種類、答える問い、状態(重複、古い、どこからもリンクされない、ナビゲーションに無い)。下書きや非公開の指定があるページは意図的なので、状態に数えない。
- 問いとページの対応を見る。ページの無い問い、違うページにある問い、問いの無いページ。
- 欠けは、求められている証拠(issue、質問、検索語)があるものだけを仕事にする。証拠が無い欠けは、「利用者に確かめる点」に回す。
- ナビゲーションのラベルは、読者の言葉で、中身を予告するものにする。「詳細」「その他」は予告しない。存在しないページを指す項目を挙げる。
- 変更の単位は、分割、統合、移動、新しいページ、改名。順は、上位の問いに効くものから。URLが変わる変更には、リダイレクトかリンクの修正を組にする。どちらもできないなら、移動と改名は案から外す。
