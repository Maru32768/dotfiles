# 読者テスト

文書だけを渡した新しいサブエージェントに、1で決めた問いへ答えさせる。親はコードと会話を知っているので、文書に欠けているものに気づけない。読者役は、文書に書いてあることしか知らない。

分かるのは、答えが書いてあるか、見出しから場所が分かるか、文書の中で食い違っていないか。読みやすさと、人が読み続けるかは分からない(「限界」)。

## 問題を作る

`<work>/questions.md`の問いを、次の3種類にして10問前後にする。

| 種類 | 数 | 作り方 |
|---|---|---|
| 上位の問い | 5〜8 | 1で決めた問い |
| 細部の問い | 2〜3 | 台帳の記述の表から、文書の後ろ半分、折りたたみ、表の中にある記述を選ぶ。組み立て直した後も探せるかを見る |
| 書いていない問い | 1 | 今の版に答えが無く、今回の変更でも足さない問い。正解は「書いていない」。読者役が背景知識で答えを作っていないかを見る |

問いには、文書の見出しや言い回しを使わず、読者の言葉で書く。「どうやって入れるのか」と書き、「Installationの節には何があるか」とは書かない。正解と根拠は、親だけが持つ。読者が複数の種類なら、読者像には最上位の読者を書き、問いには全員の分を入れる。

## 読者に渡すもの

- 版ごとに、文書を`<work>/reader/<版>/`へ写す。版の名前は、`a`と`b`のように前後が分からないものにする。複数ページなら、対象の文書と、対象からリンクで行けて問いの答えがあるページを写し、ナビゲーションの設定か目次のページも写す。後の版では、変えたページと足したページも写す。Webサイトは、描画したページの本文をテキストにして置き、節の見出しを`#`で始まる行にする。描画できなければ、ソースから書き出した骨組みを置く。
- 見出しの一覧を`<work>/reader/<版>/outline.txt`に作る。`<work>/reader/<版>/`の中で、次を相対パスで回す。コードブロックの中の`#`は拾わない。複数ページなら、ナビゲーションのラベルとページの題も並べる。

  ```bash
  awk 'FNR == 1 { f = 0 } /^[ \t]*(```|~~~)/ { f = !f; next } !f && /^#/ { print FILENAME ":" FNR ": " $0 }' <ファイル>...
  ```

- プロンプトは、下の型のままにする。埋めるのは、パス、読者、問いだけ。次を入れると、テストにならない。
  - 文書が何を扱うか、何を変えたか、なぜ変えたか
  - コード、リポジトリのパス、ほかの文書のパス
  - 親の要約、気にしている点、期待する答え
- 版ごとに、新しいサブエージェントを1つ起こす。Agentツールに`subagent_type: "general-purpose"`と`model: "sonnet"`を渡す。前の版と後の版は、同じメッセージで同時に起こしてよい。直した後の再テストも、新しいサブエージェントにする。一度読んだ読者は、初見ではない。

## プロンプトの型

```text
あなたは、次の読者として、文書を初めて読む。

読者: <1で書いた読者の状況と目的。1〜2文>

読んでよいのは、次のディレクトリのファイルだけ。ほかのファイル、リポジトリ、Webは見ない。コマンドも実行しない。
<work>/reader/<版>/

足りないものがあっても、ほかで調べない。足りないことを報告する。自分の知識で補わない。

第1部(見出しだけ)。outline.txtだけを読む。本文はまだ開かない。問いごとに、答えがありそうな見出しを1つ選ぶ。見当がつかなければ「分からない」と書く。

第2部(本文)。本文を上から1回読み、問いごとに次を書く。
- 答え。文書に書いていなければ「書いていない」
- 根拠にした文を、文書からそのまま1つ引用する。ファイルと見出しも書く
- 答えが第1部で選んだ見出しの下に無かったら、実際にあった見出し

問い:
1. <問い>

最後に、この読者として困ったところを挙げる。
- 止まったところ(どの節の、何が分からなかったか)
- 説明なしに出てきた語
- 文書が前提にしているのに、書いていないこと
- 食い違っている記述(両方を引用する)

文体や書式の感想、直し方の提案、書き直しは要らない。
```

英語の文書でも、問いと答えの言語は読者に合わせる。引用は、文書の言語のままにさせる。

## 採点

親が、問いごとに付ける。

| 判定 | 条件 |
|---|---|
| 正答 | 正解と合い、引用が文書にある(`grep -F`で確かめる) |
| 誤答 | 正解と違う。文書が誤解させている |
| 書いていない | 読者が「書いていない」と答えた。書いていない問いでは、これが正答 |
| 補った | 答えは合うが、引用が文書に無い。読者が背景知識で補っている。正答に数えない |

引用が行の折り返しをまたぐと、`grep -F`は一致しない。一致しなければ、空白と改行を1つの空白に詰めて比べ直す。

見出しだけの部は、選んだ見出しの下に実際に答えがあれば、当たりにする。

答えがほかのページにあり、そのページを渡していない問いは、行き先を正しく示した答えを正答にする。

結果は、問いごとに前と後を並べた表にする。

## 結果の使い方

- 後の版で誤答か「書いていない」になった上位の問いは、文書を直し、新しい読者でもう1回だけ試す。問いとプロンプトは変えない。
- 前の版では答えられたのに、後の版で答えられなくなった問いは、退行として必ず直す。
- 書いていない問いの答えを後の版に足すことになったら、その問いは採点から外し、報告に書く。
- 読者が挙げた困ったところは、1件ずつ、ここで直す、ほかのページの仕事(どこか)、採らない(理由)に分ける。読者が欲しがったことは欠けの証拠で、その場所に足せという指示ではない。

## 限界

- LLMは全文を読む。人は流し読みし、最初の画面で去る。順序と量の負荷は、ここでは測れない。見出しだけの部が、その一部を補う。
- LLMは背景知識が広く、書いていない専門用語や手順を補える。引用の確認と書いていない問いは、これを減らすが、無くせない。
- サブエージェントは、プロジェクトの`CLAUDE.md`を引き継ぐ。そこに書いてあることは、読者も知っている。
- 書き手と読者が同じ系列のモデルだと、書き手の書き方を読みやすく感じやすい。
- 1回の試行は揺れる。1問の差は、差とみなさない。
- 問いは親が作る。親が思いつかない読者の問いは測れない。

大きな構成変更を公開する前には、対象の読者に近い人に、同じ問いを文書だけで試してもらうよう、利用者に勧める。
