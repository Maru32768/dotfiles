# 週の枠の上限で止まる

大きい仕事が週の枠を使い切ると、利用者のほかの作業が止まる。上限は利用者が`usage-log cap <%>`で決める。上限は仕事の途中でも変わる(リセットの前日に外すなど)ので、確かめるたびに読み直す。

## 大きい仕事の本体がすること

このスキルを自分で呼ばない。スキルを呼ぶと、そのターンの残りの呼び出しがこのスキルに付き、`usage-log report --by skill`で仕事の費用が見えなくなる。次の時に、Agentツールでサブエージェントを1つ起こす(モデルは小さいものでよい)。

- 仕事を始める前
- 単位(成果物1つ、ループの1回など)を終えるたび。単位は仕事の指示に従う。指示に無ければ自分で決めて、最初の報告に書く
- サブエージェントをまとめて起こす前。起こした後の分は止められないので、1回に起こす数は、上限までの残りに見合う数にする

サブエージェントへの指示は、「usage-capスキルを呼び、その手順で週の枠の上限を確かめて、結果を返せ。仕事はするな」とする。返った1行目が`STOP`なら、新しい単位を始めずに止まり、サブエージェントの報告と、終えた単位と、再開するときに始める単位を利用者に伝えて終わる。`CONTINUE`なら続ける。どちらでもなければ、`STOP`として扱う。

## 確かめる側(サブエージェント)がすること

1. 上限を読む。`~/.local/state/usage/weekly-cap`を、このままのパスでReadで読む(Readは`~`をホームにする。自分で絶対パスを組み立てると、ホームを取り違えたときに「ファイルが無い」と区別できない)。1〜100の整数(週の枠の%)が1行ある。
   - ファイルが無ければ、上限は無い。`CONTINUE`を返す
   - 整数として読めないか、ファイルが無いこと以外でReadが失敗したら(確認を断られたなど)、`STOP`を返す
2. `mcp__ccd_session_mgmt__get_usage`を呼ぶ。遅延ロードのツールなら、先にToolSearch(`select:mcp__ccd_session_mgmt__get_usage`)で読み込む。
   - `plan.status`が`ok`なら、`plan.windows`のうち`label`が`Weekly · all models`のものの`percentUsed`を、週の消費率とする。その枠が無ければ、表示が変わったので、`STOP`を返す
   - `not_applicable`なら、プランの枠が無い(APIキーなど)ので、`CONTINUE`を返す
   - `unavailable`なら、`note`が呼び直せば読めると言うときだけ、1回呼び直す。呼び直さないときと、呼び直しても読めないときは、`STOP`を返す
   - ツールが無ければ(デスクトップアプリの外で動いている)、`STOP`を返す
   - 上のどれにも当たらなければ(ほかの`status`、`percentUsed`が無い、呼ぶのを断られたなど)、`STOP`を返す
3. 週の消費率が上限以上なら`STOP`、未満なら`CONTINUE`を返す。

返す形は、1行目に`CONTINUE`か`STOP`だけを書き、2行目から次を書く。

- 止まる理由(上限に達した、上限のファイルが読めない、`get_usage`で読めない、など)。続けるなら書かない
- 週の消費率と上限、枠がリセットされる時刻(`resetsAt`)。読めなかったものは、読めなかったと書く
- 止まるなら、再開の方法。上限に達したなら、`usage-log cap off`で上限を外すか、`usage-log cap <%>`で上げるか、リセットを待つ。上限のファイルが整数でないなら、`usage-log cap <%>`で書き直すか、`usage-log cap off`で外す。デスクトップアプリの外なら、デスクトップアプリで動かす。Readの確認を断ったなら、許可して確かめ直す。`get_usage`が読めないか、表示が変わったなら、時間をおいて確かめ直すか、上限を外して続けるかを決める。どれにするかは利用者が決める

上限のファイルは読むだけにする。外したり上げたりは、このスキルからはしない。
