# 本文の型

`{{…}}` は publish.sh が埋めるプレースホルダ。`<…>` は書く人が埋める。

## 子 PR

```markdown
## 概要

<この層が何を足すか。1〜2 文>

## なぜ要るか

<この変更が無いと何が起きるか。誰が、何のためにこれを必要とするか（後続の層は issue 番号で書く。PR 番号は本文を書く時点では決まっていない）。読み手は元の PR を読んでいないので、前提になる背景はここで説明し直す>

## なぜこの形か

<読み手が思いつく別の案と、採らなかった理由。案が 2 つ以上なら表にする。選ぶ余地の無い変更なら節ごと消す>

| 案 | 採否 | 理由 |
|---|---|---|
| <この PR の形> | 採用 | <理由> |
| <別の案> | 不採用 | <理由> |

## 変更

- <変更 1>
- <変更 2>

## レビューの観点

<読み手が引っかかりそうな点。たとえば、呼び出し元が上の層で入るので単独では過剰に見える、など。無ければ節ごと消す>

## 動作確認

{{VERIFY}}

## この PR の位置

#<元 issue> の実装（#<元 PR>）を分割した子 PR の <N> 本中 <n> 本目で、ベース PR {{BASE}} の上に積んでいる。直下の PR: {{BELOW}}

先に読む PR: {{PREREQ}}。次にレビューする PR: {{NEXT}}

QA はベース PR でまとめて行う。この PR はレビューの承認後、merge commit でベースへマージする。

Closes #<子 issue>

🤖 Generated with [Claude Code](https://claude.com/claude-code)
```

- `{{BELOW}}` は、1 本目では「なし（ベースに向いている）」になる
- `{{PREREQ}}` は、その層がコードの前提にする層の PR。下の層しか指さないので、作る時点で埋まる。無ければ「なし（ほかの子 PR とは独立に読める）」
- `{{NEXT}}` は、子 PR を全部作り終えるまで決まらない。publish.sh が最後に本文を取り直して埋める。一番上は「なし（スタックの一番上）」

## ベース PR

```markdown
## 概要

<全体で何を足すか。機能の一覧の表があれば置く>

#<元 PR> は 1 本の PR としては大きすぎたため、<N> 本の子 PR に分けた。この PR は子 PR を集めるベースになる。子 PR はレビューで承認されたらこのブランチへマージし、QA はこの PR でまとめて行う。QA OK になったら、この PR を main へマージする。

<ベースが別の PR の上に積まれているなら、その PR と、マージ後に base が付け替わることを書く>

## 子 PR

レビューは表の番号順（スタックの下から）に進めるのが基本になる。各 PR は「先に読む PR」の変更を前提にしているので、先にそちらを読むと前提が揃う。<並行してレビューしてよい PR と、早めに読んでほしい PR>

マージは、レビューが終わった順ではなく表の番号順に行う。1 本目の子 PR の base はこのブランチで、2 本目以降の base は 1 つ下の子 PR のブランチになる。下の PR をマージすると、そのブランチがリポジトリの設定により自動で消え、GitHub が上の PR の base をこのブランチへ付け替える。上の PR を先にマージすると、その変更はこのブランチではなく下の PR のブランチに入ってしまう。

| # | PR | issue | 内容 | 先に読む PR |
|---|---|---|---|---|
| 1 | {{PR:<層>}} | #<子 issue> | <内容> | — |
| 2 | {{PR:<層>}} | #<子 issue> | <内容> | {{PR:<前提の層>}} |

## 運用

- 子 PR もこの PR も merge commit でマージする。子 PR を squash すると、その上に積んだ PR の差分に下の PR の変更が混ざる。この PR を squash すると main では 1 コミットになり、子 PR の単位で revert できなくなる
- 必須チェックは main にしかかからない。子 PR は、CI が緑であることを確かめてからマージする
- `Closes` は main に向けた PR でしか効かないため、子 issue は子 PR をこのブランチへマージした時点で手で閉じる
- QA で見つけたバグは、このブランチに向けた子 PR で直す

## マージ前の作業

<main を取り込むタイミング、依存の検証ファイルの再生成など。無ければ節ごと消す>

## 範囲外

- <この PR ではやらないこと>

## テストケース

- [ ] <QA テストケースを同梱する>

<QA の定型文があれば、ここに置く>

Closes #<元 issue>

🤖 Generated with [Claude Code](https://claude.com/claude-code)
```

- `{{PR:<層>}}` は、publish.sh がベース PR の本文のどこにあっても子 PR の番号に置き換える。「先に読む PR」の列にも使える

## 元の PR を閉じるコメント

```markdown
<N> 本の子 PR に分けて出し直したので閉じます。子 PR はベース PR {{BASE}} に集めてから、main へマージします。内容はこの PR の最終状態と同じです（子 PR をすべて積んだ先端のツリーは、この PR の head `<短い SHA>` のツリーと一致します）。
```
